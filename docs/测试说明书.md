# 测试说明书

**版本号：** V1.1
**编制日期：** 2026年7月15日
**编制队伍：** DDL
**关联文档：** 《软件需求规格说明书（SRS）》V1.0、《系统开发说明书》V1.1、A3赛题完整要求

## 1. 引言

### 1.1 编写目的

本说明书规定系统的测试范围、环境、策略、用例设计、进入/退出准则与缺陷管理流程，用于验证系统是否满足《软件需求规格说明书（SRS）》定义的全部功能需求（FR-1～FR-5）与非功能需求（NFR-1～NFR-21），以及赛题对界面交互、内容安全、多智能体架构与课程知识库的约束。

测试以**SRS理想验收口径**为唯一标准：凡SRS写明的指标与规则，均设计对应用例；未通过项记为缺陷并纳入修复清单，不得以“当前实现简化”为由直接豁免（豁免仅可在变更控制委员会正式变更SRS后生效）。

### 1.2 测试对象

| 对象 | 范围说明 |
|---|---|
| 多智能体编排层 | Supervisor、画像/路径/资源/学伴等智能体协同 |
| 核心算法模块 | Q2K、DAG解析、群体MDP、IRT、受控解码、沙箱闭环、内容安全 |
| 后端API与SSE | 会话、画像、路径、资源、答疑、评估、沙箱 |
| Web前端 | 流式对话、Markdown、多模态卡片、DAG看板、雷达图 |
| 初始课程知识库 | ≥1门完整课程；DAG≥30节点；Q2K种子≥50条 |
| 部署与配置 | 环境变量密钥管理、Docker隔离、备份策略 |

### 1.3 测试依据

1. 《软件需求规格说明书（SRS）》V1.0全文；
2. 《系统开发说明书》V1.1；
3. A3赛题基本功能、非功能、测试数据与文档要求；
4. 本说明书定义的用例与通过准则。

### 1.4 测试原则

1. **需求可追溯**：每个用例映射到FR/NFR编号；
2. **先必须后加分**：FR-1/2/3与关键NFR为发布阻塞项；FR-4/5为加分项但仍须按SRS测；
3. **正反结合**：功能正确性 + 安全/异常/边界；
4. **可重复**：固定测试账号、课程主题与种子数据；
5. **证据留存**：截图、SSE日志、Supervisor路由日志、沙箱编译日志。

### 1.5 测试分层模型

```Plain Text
graph TB
    L0[静态检查与配置门禁] --> L1[单元/模块测试]
    L1 --> L2[接口契约测试]
    L2 --> L3[智能体协作集成测试]
    L3 --> L4[端到端业务场景测试]
    L4 --> L5[非功能：性能/安全/可靠性/UX]
    L5 --> L6[验收与演示彩排]
```

| 层级 | 目的 | 主要方法 |
|---|---|---|
| L0 | 密钥未硬编码、依赖可安装、服务可起 | 清单检查 |
| L1 | Schema校验、融合评分、DFS、相似度 | pytest等 |
| L2 | REST/SSE字段完整、错误码可读 | httpx/Postman |
| L3 | 四智能体协作、子图并行、事件广播 | 场景脚本+日志 |
| L4 | 学习闭环可跑通 | 浏览器实操 |
| L5 | NFR指标达到SRS | 计时/压测/负例 |
| L6 | 7分钟演示可复现 | Demo Script |

## 3. 进入与退出准则

### 3.1 测试进入准则

1. SRS与开发说明书基线已冻结（或变更已登记）；
2. ENV-01～ENV-09全部通过；
3. 测试账号与数据包准备完毕；
4. 日志采集开关打开（Supervisor路由、子图Send、沙箱、安全）。

### 3.2 发布/演示退出准则（阻塞项）

| 类别 | 条件 |
|---|---|
| 功能 | FR-1、FR-2、FR-3 下全部P0用例Pass |
| 协作 | 学习包流程可证明≥4智能体参与 |
| 资源 | 单次稳定产出≥5类经验证资源 |
| 交互 | 流式+Markdown+卡片无明显阻断缺陷 |
| 安全 | TC-SAFE与NFR-11相关P0全部Pass |
| 缺陷 | 无Blocker；无未关闭Critical |

加分项FR-4/FR-5：若申报加分，则其P0用例也必须Pass；否则在报告中明确“未纳入加分申报”。

## 7. 端到端场景测试

### 7.1 E2E-01 主学习闭环（阻塞）

```Plain Text
flowchart TD
    A[新学生登录/进入] --> B[≥3轮对话构建6维画像]
    B --> C[指定目标知识点]
    C --> D[DAG薄弱前置定位]
    D --> E[MDP先验路径生成]
    E --> F[并行生成≥5类资源并校验]
    F --> G[节点卡片学习与练习]
    G --> H[权重跨阈值触发重规划]
    H --> I[看板刷新与建议]
```

**通过标准：** 单人可独立在约定时间内完成；Supervisor日志可证明多智能体协作；五类资源均可展开且代码类有沙箱通过凭证。

### 7.2 E2E-02 口语答疑闭环（加分申报时阻塞）

口语含指代提问 → Q2K四阶段 → 实体资源包（≥3形式）→ 用户追问仍保持上下文 → 低分问句RAG兜底。

### 7.3 E2E-03 学伴互教与评估

学伴FSM提问 → 学生讲解 → 评估写回行为日志 → 画像增量 → 评估看板变化。

### 7.4 E2E-04 异常与恢复

LLM超时、沙箱未启动、资源局部失败、页面刷新、会话切换：均须有明确提示且主服务可恢复。
