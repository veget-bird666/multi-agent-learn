# 系统全貌图：AI 个性化学习多智能体系统

## 一、一句话理解新模式

把你熟悉的传统后端和现在的多 Agent 模式做个对比：

```
传统后端：                         多 Agent 模式：

请求 → 路由 → service → 数据库    请求 → 路由 → 图引擎 → state → Agent1 → state → Agent2 → ...
  ↑              ↑                 ↑                                     ↑
  每个函数各管各的                所有节点读写同一份 state
  的参数和返回值                     (就像一块共享白板)
```

**state 就是一块共享白板**，每个 Agent 在上面写自己的结果，下一个 Agent 读来用。

## 三、State 数据流（核心概念）

```python
# 1. 用户发消息 → 路由层构造初始 state
initial_state = {
    "student_id": "小明",
    "message": "我喜欢数学但总是粗心",
    "history": [HumanMessage("我喜欢数学但总是粗心")],
    "profile": None,          # 待填充
    "knowledge_point": None,   # 待填充
    "learning_path": None,     # 待填充
    ...
}

# 2. Supervisor 读 state，下一步 → profile_agent
#    判断依据：profile == None

# 3. profile_agent 执行：
def profile_agent(state):
    # 从白板上读
    history = state["history"]

    # 调 LLM
    profile = llm.with_structured_output(StudentProfile).invoke(...)

    # 在白板上写
    return {"profile": profile, "next_agent": "path_agent"}

# 现在的 state 变成：
state = {
    ...
    "profile": StudentProfile(...),   # ✅ 被写入了
    "knowledge_point": None,          # 还没写
    ...
}

# 4. Supervisor 再次读 state，下一步 → path_agent
#    判断依据：profile != None, learning_path == None

# 5. 以此类推...每个 Agent 读自己需要的，写自己产出的
```

## 四、7 个 Agent 的分工

```
Agent          读什么                         写什么
───────        ──────                         ──────
profile_agent  history, student_id            profile
path_agent     profile                        learning_path, knowledge_point
resource_agent profile, knowledge_point       generated_resources, response
error_sim_agent knowledge_point               response (含纠错内容)
buddy_agent    knowledge_point                response (含互动问题)
curiosity_agent interaction_pattern           interaction_pattern (更新)
reflection_agent teaching_decisions, profile  response (含评估)

Supervisor     读取以上所有字段               next_agent (决定下一步)
```

## 六、类比：传统后端 → 多 Agent 模式

| 传统后端概念 | 多 Agent 对应 | 类比 |
|---|---|---|
| 函数参数 | `state["xxx"]` | 你不需要传参了，从白板上拿 |
| 函数返回值 | `return {"xxx": value}` | 你把结果写回白板 |
| 调用链 `f1→f2→f3` | `Supervisor→AgentA→Supervisor→AgentB` | 不再是硬编码调用，由调度员决定 |
| if-else 判断 | `state["xxx"] == None` | 你看白板上有没有数据就知道该做什么 |
| 每个请求独立的变量 | 同一个 state 贯穿全程 | 所有 Agent 共享上下文 |
