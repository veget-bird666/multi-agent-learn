## 1. 引言

### 1.1 编写目的

本文档依据《软件需求规格说明书（SRS）》V1.0，系统阐述「基于大模型的个性化资源生成与学习多智能体系统」的设计思路、技术选型、多智能体协同框架、核心模块实现方法、数据与接口设计、界面实现、部署运维及前沿AI技术融合实践，作为开发实现、联调集成、质量评审与竞赛提交的技术依据。

文档重点回答以下问题：

1. 系统如何以多智能体架构落实赛题「画像构建—资源生成—路径推送—辅导评估」全链路；
2. 讯飞星火大模型、Spark Embedding、沙箱自校验、受控解码、Q2K、群体MDP等关键技术如何落地到模块与接口；
3. 如何保障资源交付的可验证性、交互体验的现代AI产品规范，以及开源组件合规使用。

### 1.2 项目背景

在高等教育数字化转型进程中，标准化教学模式与学生个体差异之间的矛盾日益突出。不同学生在知识基础、认知风格、学习动机和元认知能力等方面存在显著差异，传统课堂讲授模式难以兼顾每一位学生的个性化学习需求。与此同时，以通用大模型、多模态生成技术为代表的前沿AI技术体系正在高速发展，具备了强大的自然语言理解、多模态内容生成和复杂推理能力，为教育领域的个性化变革提供了全新的技术可能。

本项目的核心目标是构建一套面向高等教育的个性化学习多智能体系统，以电子信息/计算机类《C语言程序设计》等课程为切入点，实现从学生画像动态建模、个性化多模态资源生成、学习路径智能规划到答疑辅导与效果评估的全链路智能化闭环，切实推动“因材施教”在数字化时代的深度落地。

## 2. 系统总体设计

### 2.1 设计原则

1. **需求驱动分层**：数据层、核心功能模块层、多智能体协作层、用户交互层四级对齐SRS第2.3节；
2. **协作优于堆叠**：任何「个性化学习包」生成必须体现至少4类专业智能体协作，禁止单模型一次直出；
3. **先校验后交付**：代码类资源必须经Docker沙箱闭环；习题须经符号/结构校验；文档与导图须经Schema校验；
4. **状态可共享、节点可插拔**：智能体间仅通过标准化状态字段与消息接口协作（NFR-14）；
5. **体验符合现代AI产品规范**：流式输出、Markdown渲染、多模态卡片化、进度可追踪（NFR-18～21）。

### 2.2 用户角色与系统边界

| 角色 | 职责边界 |
|---|---|
| **学生** | 对话构建画像、学习路径推进、资源使用、学伴互动、问答、查看评估看板 |
| **系统管理员** | 监控运行状态、维护初始课程知识库与DAG、审核Q2K自生长条目、审计行为日志 |

系统不依赖外部第三方教育平台；课程知识库、Q2K问法库、画像与行为数据均本地构建与管理。对外接口包括：学生Web界面、讯飞星火/Embedding服务、Docker沙箱执行环境。

## 3. 多智能体协同框架详细设计

### 3.1 共享状态 LearningState

LearningState是「共享白板」，任一智能体只读写自身职责字段，严禁跨职责隐式副作用。

| 字段分组 | 关键字段 | 类型/语义 | 写入方 | 读取方 |
|---|---|---|---|---|
| 会话基础 | student_id, session_id, message, history | 标识与对话上下文 | API/chat | 全体 |
| 画像 | profile_vector[6], profile_meta, portrait_version | SRS六维\[0,1\]向量 | 画像诊断智能体 | 路径/资源/学伴/评估 |
| 知识与路径 | target_kp, weak_prerequisites, learning_path, resource_strategy_ids | DAG与路径序列 | 路径规划智能体 | 资源调度/前端 |
| 生成产物 | generated_resources[], validation_reports[] | 卡片与校验报告 | 资源调度智能体 | 学伴/前端 |
| 交互模式 | interaction_pattern, buddy_fsm_state | 好奇/卡壳/学伴状态 | 学伴/好奇心分析 | Supervisor |
| 教学决策 | teaching_decisions[], needs_rollback | 后悔机制与回滚标记 | 评估/反思节点 | 路径规划 |
| 调度控制 | next_agent, operation, enable_* | 路由与开关 | Supervisor/用户 | 图路由 |

### 3.2 Supervisor 动态调度

系统不使用硬编码流水线，而采用Supervisor循环图：所有专业智能体执行完毕后回到Supervisor，由星火大模型基于当前状态结构化决策下一步。

```Plain Text
sequenceDiagram
    participant U as 学生
    participant API as FastAPI
    participant S as Supervisor
    participant P as 画像诊断
    participant Path as 路径规划
    participant R as 资源调度
    participant B as 学伴交互
    U->>API: 请求个性化学习包/问答
    API->>S: 初始化LearningState
    S->>P: 画像缺失或需刷新
    P-->>S: profile_vector + version
    S->>Path: DAG+MDP规划路径
    Path-->>S: learning_path + strategy_ids
    S->>R: 并行生成≥5类资源
    R-->>S: 经验证资源卡片
    S->>B: 决定推送时机与学伴介入
    B-->>S: 流式回复/引导
    S-->>API: FINISH
    API-->>U: SSE状态+Token+卡片
```

**调度硬规则：**

1. 最大迭代次数上限，防止死循环；
2. 画像首次构建完成前，禁止进入高级资源批量生成（可先答疑）；
3. 路径重规划不打断当前正在学习的节点，变更在下一节点生效（SRS 3.3.3）；
4. 用户可关闭路径规划/资源生成开关，Supervisor必须尊重硬约束。

### 3.3 四类核心智能体职责（SRS 3.2.2）

| 智能体 | 核心职责 | 输入 | 输出 |
|---|---|---|---|
| **画像诊断智能体** | 构建与动态刷新6维画像；广播画像变更事件 | 对话流、行为日志 | profile_vector、变更事件、版本号 |
| **路径规划智能体** | DAG拓扑合规 + 群体MDP先验 → 个性化序列 | 画像、DAG、MDP转移矩阵 | 有序知识点序列 + 资源策略ID |
| **资源调度智能体** | 解析策略、并行调度≥5类生成器、控制沙箱验证 | 策略列表、画像、DAG | 经验证多模态资源卡片集 |
| **学伴交互智能体** | FSM+行为树控制语调/提问/错误注入 | 画像、行为树配置、上下文 | 学伴自然语言流 |

除上述四类核心角色外，工程实现中可扩展：答疑chat节点、查询改写节点、工具节点、错误模拟节点、好奇心节点、效果评估节点，均在Supervisor统一调度下工作，属于同一多智能体协同框架。

### 3.4 「个性化学习包」标准协作流程（SRS 3.2.3）

1. 画像诊断智能体推送当前学生6维画像；
2. 路径规划智能体查询目标知识点依赖链，并在群体MDP中检索相似画像Top-5高增益轨迹，融合生成个性化序列；
3. 资源调度智能体按节点策略并行分发5类生成器；
4. 各资源经沙箱/Schema/符号校验后封装为卡片；
5. 学伴交互智能体按行为树决定呈现时机与引导方式，经SSE推送前端。

### 3.5 资源生成子图（Map-Reduce）

```Plain Text
flowchart TB
    planner[资源计划器] -->|Send并行| d[讲解文档生成器]
    planner --> m[思维导图生成器]
    planner --> e[差异化习题生成器]
    planner --> c[代码案例生成器]
    planner --> r[拓展阅读/视频检索生成器]
    e --> ev[结构/符号校验反射]
    c --> cv[Docker沙箱自校验闭环]
    d --> schema1[Schema受控校验]
    m --> schema2[Schema/Mermaid校验]
    r --> align[Q2K实体对齐检查]
    ev & cv & schema1 & schema2 & align --> safe[内容安全与防幻觉过滤]
    safe --> collector[卡片封装汇总]
```

并行度由策略ID列表决定；任一生成器失败可局部重试，不拖垮整包。代码链路必须执行「生成→编译→日志回喂→Debug→再编译」闭环，平均完整闭环≤10秒（含最多3次重试，NFR-3）。

## 4. 核心功能模块设计与实现

### 4.1 对话式动态学生画像构建（SRS 3.1 / FR-1）

#### 4.1.1 模块目标

摒弃表单，以讯飞星火多轮流式对话自动抽取特征，输出不少于6维、值域\[0,1\]的画像向量，并支持随学随新与版本追溯。

#### 4.1.2 六维向量定义

| 维度下标 | 维度名称 | 语义 | 量化方式示例 |
|---|---|---|---|
| 0 | 知识基础 | 先修与当前水位 | 自述+测评映射到\[0,1\] |
| 1 | 认知风格 | 实例/公式/实践倾向 | 对话偏好编码为连续值或多峰投影 |
| 2 | 易错偏好 | 典型错误类型强度 | 历史错因聚类强度 |
| 3 | 遗忘曲线参数 | 保持/衰减特征 | 间隔复习表现拟合 |
| 4 | 学习动机强度 | 主动性与目标清晰度 | 目标陈述与行为活跃度 |
| 5 | 元认知水平 | 自我监控与策略调整 | 学伴互教与纠错主动性 |

画像张量记为 $S\in\mathbb{R}^{d}$（实现取 $d=6$）。

#### 4.1.3 实现流程

```Plain Text
flowchart LR
    A[预置首问模板] --> B[3-5轮流式对话]
    B --> C[星火结构化抽取]
    C --> D[映射为6维0-1向量]
    D --> E[写入画像库+版本号]
    E --> F[广播变更事件]
    G[行为日志流] --> H[滑动窗口加权重算]
    H --> E
```

- **FR-1.1**：首问模板 + 动态追问，轮次≥3，话术避免机械填表；
- **FR-1.2**：每次完整输出6维向量；
- **FR-1.3**：练习正确率、资源偏好、问答、学伴表现触发增量更新，近期权重大；
- **FR-1.4**：每次变更追加版本记录，支持时间轴回溯。

#### 4.1.4 关键接口

| 接口 | 说明 |
|---|---|
| 对话图触发画像节点 | 主路径构建/刷新 |
| `GET /api/profile/{student_id}` | 查询当前画像 |
| `GET /api/profile/{student_id}/history` | 版本时间线 |
| 内部事件 `portrait.updated` | 通知路径/资源/评估模块 |

| 编号 | 资源类型 | 个性化策略 | 技术保障 |
|---|---|---|---|
| FR-2.1 | 专业课程讲解文档 | 认知风格决定实例/推导/类比策略；防越阶 | 受控解码JSON Schema；依赖解析器 |
| FR-2.2 | 知识点思维导图 | DAG层级 + 薄弱前置红色高亮 | Schema保证结构完整，前端Mermaid渲染 |
| FR-2.3 | 差异化练习题 | 易错偏好设计干扰项；难度随Weight调整 | 符号计算/结构校验闭合答案 |
| FR-2.4 | 代码类实操案例 | 高水位Skeleton，低掌握Step-by-Step | Docker沙箱闭环；iFlyCode规则链AST校验 |
| FR-2.5 | 拓展阅读/应用案例 | 动机强度与专业方向匹配延伸材料 | Q2K实体ID对齐，避免碎片拼接 |

实现上可扩展PPT、短视频讲解、图解卡片等，作为多模态增强，但仍以五类必须资源为验收底线。

#### 4.2.2 受控解码与交付门禁

1. 生成阶段：LLM输出必须能被目标Schema解析；失败则反射重试；
2. 代码阶段：进入沙箱编译运行；失败日志回喂Debug直至通过或达重试上限；
3. 安全阶段：敏感词 + LLM审查 + 知识一致性检查；
4. 通过后方可写入资源表并推送卡片——**严禁LLM原生未校验文本直出前端（NFR-7）**。

#### 4.2.3 个性化学习包时序指标

一次性生成5种类型资源端到端时间目标≤30秒，必须提供进度条或流式逐步呈现，禁止白屏（NFR-4）。

### 4.3 个性化学习路径规划与资源推送（SRS 3.3 / FR-3）

#### 4.3.1 知识点DAG

每个节点包含：`node_id, name, state, weight, prerequisites[], level`。

- State：已掌握 / 学习中 / 未开始；
- Weight：基于IRT估计的掌握度，区间\[0,1\]；
- 须可可视化，且拓扑排序校验无环。

初始课程知识图谱不少于30个知识节点（SRS 5.2）。

#### 4.3.2 逆向DFS薄弱点定位（FR-3.2）

当学生指定目标 $K_i$：

$$
\text{Weak\_Prerequisites}(K_i)=\{K_j\mid K_j\in \text{Ancestors}(K_i)\land \text{Weight}(K_j)<0.6\}
$$

薄弱前置高亮并给出导航建议。

#### 4.3.3 群体经验迁移（FR-3.3）

使用余弦相似度检索与新用户最相似的历史轨迹Top-5：

$$
\text{Similarity}(S_{\text{new}}, S_{\text{history}})=\frac{S_{\text{new}}\cdot S_{\text{history}}}{\|S_{\text{new}}\|\cdot\|S_{\text{history}}\|}
$$

提取其最优转移概率矩阵作为先验，引导大模型生成**100%满足DAG依赖**的路径；相邻节点必须满足前置依赖已出现；每个节点附带资源策略ID。

#### 4.3.4 卡片化精准推送与动态重规划

- FR-3.4：按路径顺序封装文档/代码/导图/习题/视频等卡片，节点点亮可展开；
- FR-3.5：节点Weight跨阈值（如0.55→0.75）触发重规划，响应≤3秒，且不违反DAG；变更在下一节点生效。

路径规划计算时间目标≤3秒（含DAG检索+MDP查询+LLM推理，NFR-5）。

### 4.4 智能辅导答疑与Q2K（SRS 3.4 / FR-4，加分）

#### 4.4.1 Q2K四阶段管线

| 阶段 | 处理 | 技术 | 产出 |
|---|---|---|---|
| Stage1 | 意图重写与指代消解 | 星火 + 多轮Context | 标准学术问句 |
| Stage2 | 双路混合检索 | BM25 + Spark Embedding | 候选列表 + 融合分 |
| Stage3 | 图谱实体ID直出 | 融合分≥0.65 | Knowledge_Point_ID + 标准解答卡片 |
| Stage4 | 长尾聚类自生长 | HDBSCAN + 异步回写 | 问法库持续进化 |

融合评分：

$$
\text{Score}_{\text{final}}=0.3\times\text{Score}_{\text{BM25}}+0.7\times\text{Score}_{\text{SparkEmbedding}}
$$

默认阈值 $\tau=0.65$，可由管理员调整。低分必须降级传统RAG，保证100%有回复（NFR-9）。问法库更新采用双缓冲（主库+增量库）。

#### 4.4.2 多模态辅导输出

命中标准库后，不返回碎片文本，而是通过实体ID联动依赖解析器，调取完整教学资源包（讲解+代码+习题，≥3种形式）。复杂问题组合：文字解答、图解说明、短视频讲解。

口语化测试目标：10条典型用例意图还原准确率≥85%（FR-4.1）。

#### 4.4.3 学伴FSM与行为树

学伴智能体以FSM管理宏观状态（打招呼/提问/倾听/纠错/鼓励/结束），以行为树管理微观策略（是否注入典型错误、提示粒度、追问强度）。画像中元认知与动机维度影响行为树参数，实现“水平略低的同学被学生教会”的巩固机制。

### 4.5 学习效果评估与动态反馈（SRS 3.5 / FR-5，加分）

#### 4.5.1 行为数据采集（≥6类）

资源阅读时长、练习正确率（首次/重试）、代码编译成功率、解题耗时、节点切换频率、学伴交互质量等，均带时间戳与知识点ID。

#### 4.5.2 IRT掌握度估计

将答题正误转化为Weight∈\[0,1\]：初期Bayes推断，数据充足后MLE优化。测试集上与人工阅卷相关系数目标≥0.75。

掌握度阈值着色：

- 绿：$\text{Weight}\ge 0.8$
- 黄：$0.6\le\text{Weight}<0.8$
- 红：$\text{Weight}<0.6$

#### 4.5.3 看板与闭环

- 雷达图展示6维画像；
- 桑基/层级图展示DAG掌握度色阶；
- 折线展示进度趋势；刷新延迟≤2秒（FR-5.3）；
- Weight跨0.3/0.6/0.8阈值且存在未纳入路径的薄弱前置时，5秒内触发重规划并提示（FR-5.4）。

#### 4.5.4 后悔机制与路径回滚（创新扩展）

系统记录每次教学决策（策略A而非B）。若后续表现显著下滑，反思评估节点对比反事实增益；若B更优，则标记`needs_rollback`，由路径规划智能体生成回滚建议并征求学生确认。

- 看板色阶即时反馈，形成「学—练—评—调」心智模型；
- 开关式控制路径/资源，尊重学生当前意图。
