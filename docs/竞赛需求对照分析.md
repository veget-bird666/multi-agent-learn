# 竞赛需求 vs 项目现状 对照分析

> 赛题：基于大模型的个性化资源生成与学习多智能体系统开发（科大讯飞 A3 赛题）
> 更新日期：2026-07-14

---

## 一、基本功能需求（45% 评分项）

### 1. 对话式学习画像自主构建

| 竞赛要求 | 项目现状 | 状态 |
|---|---|---|
| 通过自然语言对话自动抽取特征 | `profile_agent` 通过 LLM 从对话历史抽取画像 | ✅ |
| 至少 6 个维度 | **7 维度**：专业、知识基础、认知风格、学习节奏、兴趣领域、易错点偏好、学习目标 | ✅ |
| 支持画像的随学随新 | 每轮对话均调用 `profile_agent`，结合 `profile_update_hint` 增量更新 | ✅ |

**涉及文件：** `backend/app/agents/profile_agent.py`、`backend/app/models/user.py`、`backend/app/services/profile_service.py`

### 2. 多智能体协同的资源生成

| 竞赛要求 | 项目现状 | 状态 |
|---|---|---|
| 体现"多智能体"架构设计 | Supervisor + 8 个 Agent 的 LangGraph 循环调度架构 | ✅ |
| 至少 5 种个性化资源 | **8 种**：文档、试卷、PPT、图片、视频、思维导图、拓展阅读、代码案例 | ✅ |
| 多智能体协作完成 | Supervisor 规划 → rewrite_node 查询重写 → resource_agent 子图 → planner 并行派发 → 各生成器 → safety_filter → collector | ✅ |
| 资源生成质量保障 | exam/code 走"生成→反思→重试"链路，验证不通过最多重试 2 次 | ✅ |

**资源类型对照：**

| 竞赛要求的类型 | 对应实现 | 文件 |
|---|---|---|
| 专业课程讲解文档 | `doc_generator` | `backend/app/resource_subgraph/doc_generator.py` |
| 知识点思维导图 | `mindmap_generator` | `backend/app/resource_subgraph/mindmap_generator.py` |
| 不同类型练习题目 | `exam_generator` (+ `exam_reflector`) | `backend/app/resource_subgraph/exam_generator.py` |
| 拓展阅读材料 | `reading_retriever` (RAG 检索) | `backend/app/resource_subgraph/reading_retriever.py` |
| 多模态教学视频/动画 | `video_retriever` | `backend/app/resource_subgraph/video_retriever.py` |
| 代码类实操案例 | `code_generator` (+ `code_reflector`) | `backend/app/resource_subgraph/code_generator.py` |
| PPT 课件 | `ppt_generator` | `backend/app/resource_subgraph/ppt_generator.py` |
| 图片/图示 | `image_retriever` | `backend/app/resource_subgraph/image_retriever.py` |

### 3. 个性化学习路径规划和资源推送

| 竞赛要求 | 项目现状 | 状态 |
|---|---|---|
| 科学、动态的个性化学习路径 | `path_agent` 根据学生画像和知识点规划多阶段路径 | ✅ |
| 明确学习步骤和顺序 | 路径包含 `steps[]`，每步有 order、stage_name、knowledge_points、difficulty | ✅ |
| 基于画像的资源精准推送 | 资源通过 `path_id` + `step_order` 绑定到路径阶段，按阶段筛选推送 | ✅ |
| 涵盖多类型内容 | 文档/视频/题库/实操案例等 8 种类型 | ✅ |
| 多路径管理 | 支持创建多条路径、切换 active 路径、CRUD 操作 | ✅ |

**涉及文件：** `backend/app/agents/path_agent.py`、`backend/app/services/learning_path_service.py`、`backend/app/database/models.py`（LearningPathORM）

| 竞赛要求 | 项目现状 | 状态 |
|---|---|---|
| 标注开源项目名称、来源、协议 | 项目使用了 LangGraph、LangChain、FastAPI、Vue 3、Tailwind、SQLAlchemy 等，**未在文档中标注** | ❌ |

### 3. 防幻觉与内容安全

| 竞赛要求 | 项目现状 | 状态 |
|---|---|---|
| 事实性错误检查 | `llm_fact_check()` — LLM 验证事实准确性 | ✅ |
| 敏感违规信息过滤 | `keyword_scan()` — 5 类敏感词库 + `llm_safety_check()` — LLM 安全审查 | ✅ |
| 系统级安全机制 | `safety_filter` 节点在资源子图中对每个资源逐一检查，未通过的被 collector 过滤 | ✅ |
| 不阻塞生成流程 | 异常时默认 PASS，不阻塞主流程 | ✅ |

**涉及文件：** `backend/app/core/content_safety.py`、`backend/app/resource_subgraph/safety_filter.py`

### 4. 响应时间

| 竞赛要求 | 项目现状 | 状态 |
|---|---|---|
| 合理响应时间 | Docker 沙箱 20s 超时，LLM 调用使用较快模型（DeepSeek V3） | ✅ |
| 生成进度追踪 | SSE `status` 事件实时推送 Agent 状态（画像分析、路径规划、资源生成等） | ✅ |
| 流式呈现机制 | `token` 事件流式推送回复文本，避免白屏等待 | ✅ |
