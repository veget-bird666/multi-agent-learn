# 虚拟内存管理

## 为什么需要虚拟内存？

物理内存有限，但程序需求不断增长。虚拟内存让 OS 用**磁盘扩展内存**，使更多程序能在有限 RAM 中运行。

理想存储器：更大、更快、更便宜、非易失——现实中不存在单一介质满足所有需求，因此采用分层存储。

## 三种内存扩展技术对比

| 技术 | 粒度 | 谁负责 | 特点 |
|:---|:---|:---|:---|
| 覆盖 (Overlay) | 模块级 | 程序员手动 | 不同时执行的模块共享内存 |
| 交换 (Swapping) | 进程级 | OS 自动 | 整个进程换入/换出 |
| 虚拟内存 | 页/段级 | OS 自动 | 只换入/换出需要的部分 |

### 覆盖技术

程序员将程序划分为功能模块，按需装入：
- 必要部分常驻内存
- 不常用部分留在外存，需要时再装入
- **缺点**：增加编程复杂度，以时间换空间

### 交换技术

将整个进程换出到磁盘，需要时换入：
- **换出 (Swap Out)**：进程从内存写到外存
- **换入 (Swap In)**：从外存读回内存
- **缺点**：以整个地址空间为单位，开销大

## 程序局部性原理

虚拟内存可行性的理论基础：

**时间局部性**：最近访问的数据/指令，短期内可能再次访问

**空间局部性**：当前访问的数据附近，短期内可能被访问

### 经典例题：二维数组访问

页面大小 4KB，每进程 1 个物理页，数组 `int A[1024][1024]` 按行存储：

```c
// 方法1：列优先 → 1024×1024 次缺页
for (j = 0; j < 1024; j++)
    for (i = 0; i < 1024; i++)
        A[i][j] = 0;

// 方法2：行优先 → 1024 次缺页
for (i = 0; i < 1024; i++)
    for (j = 0; j < 1024; j++)
        A[i][j] = 0;
```

行优先访问符合空间局部性，缺页率远低于列优先。

## 虚拟内存的基本特征

1. **大的用户空间**：虚拟地址空间可大于物理内存（32 位 → 4GB 虚拟，256MB 物理）
2. **部分交换**：只换入/换出部分页面，而非整个进程
3. **不连续性**：物理分配和虚拟使用都不必连续

## 虚拟页式内存管理

在页式管理基础上增加**请求调页**和**页面置换**。

### 页表表项扩展

| 字段 | 含义 |
|:---|:---|
| 逻辑页号 | 虚拟页编号 |
| 驻留位 | 0 = 在外存，1 = 在内存 |
| 保护位 | 只读 / 读写 / 可执行 |
| 修改位 (dirty) | 页是否被修改（换出时决定是否写回） |
| 访问位 | 是否被访问（用于置换算法） |
| 物理页帧号 | 对应的物理帧 |

### 缺页中断处理流程

```
1. 访问页面 p → 查页表，驻留位 = 0 → 缺页中断
2. 若有空闲帧 → 分配帧 f；否则 → 页面置换算法选牺牲帧
3. 若牺牲页被修改 → 写回外存
4. 从外存读入页 p 到帧 f
5. 更新页表：驻留位 = 1，帧号 = f
6. 重新执行引发缺页的指令
```

### 后备存储

未被映射的页存放在：
- **交换空间 (Swap Space)**：磁盘上的专用区域
- **可执行文件**：代码段直接映射到 `.exe`/`.so`
- **共享库文件**：动态链接库的映射

## 有效访问时间 (EAT)

```
EAT = 内存访问时间 × (1 - p) + 缺页处理时间 × p
```

其中 p 为缺页率。

**示例**：内存访问 10ns，磁盘访问 5ms，缺页率 p = 0.001：
```
EAT ≈ 10 × 0.999 + 5,000,000 × 0.001 ≈ 5010 ns
```

一次缺页的开销相当于约 50 万次正常内存访问——**降低缺页率至关重要**。

## 学习要点总结

1. 虚拟内存 = 分页 + 按需调页 + 页面置换，由 OS 自动管理
2. 局部性原理是虚拟内存有效性的理论基础
3. 程序编写方式（如数组遍历顺序）直接影响缺页率
4. 缺页中断处理是虚拟内存的核心机制
5. EAT 公式说明：即使缺页率很低，磁盘 I/O 也会极大拖慢性能
