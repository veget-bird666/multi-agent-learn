# 死锁与进程间通信

## 死锁 (Deadlock)

### 什么是死锁？

一组进程各自持有资源，又等待其他进程持有的资源，形成**循环等待**，所有进程都无法继续。

**经典示例**：两个磁带驱动器，P1 和 P2 各持一个，各需另一个。

### 资源分配图

```
进程 P ──请求──→ 资源 R ──分配──→ 进程 Q
  ↑                              │
  └──────────请求─────────────────┘
         （形成环 → 死锁）
```

- 无环 → 无死锁
- 有环 + 每类资源只有一个实例 → 一定死锁
- 有环 + 多实例 → 可能死锁

### 死锁四个必要条件

| 条件 | 含义 |
|:---|:---|
| 互斥 | 资源同一时刻只能被一个进程使用 |
| 持有并等待 | 进程持有资源的同时等待其他资源 |
| 不可抢占 | 资源只能由持有者主动释放 |
| 循环等待 | 存在进程等待链形成环 |

四个条件**同时成立**才死锁——破坏任一条件即可预防。

## 死锁处理方法

| 策略 | 思路 | 代表 |
|:---|:---|:---|
| 预防 | 破坏四个必要条件之一 | 资源有序分配 |
| 避免 | 动态检查，确保系统始终安全 | 银行家算法 |
| 检测 | 允许死锁发生，定期检测并恢复 | 资源分配图化简 |
| 忽略 | 假装没有死锁 | UNIX 大多数情况 |

### 预防策略

- **破坏互斥**：使资源可共享（不适用于所有资源）
- **破坏持有并等待**：一次性申请所有资源（利用率低）
- **破坏不可抢占**：等待时释放已占资源
- **破坏循环等待**：资源按序编号，按序申请

### 避免：银行家算法

系统检查分配后是否处于**安全状态**——存在安全序列，使所有进程都能完成。

```
安全序列 <P1, P2, ..., Pn>:
  对每个 Pi，Pi 所需资源 ≤ 可用 + 所有 Pj(j<i) 持有的资源
  → Pi 可完成并释放资源 → Pi+1 可完成 → ...
```

- 安全 → 无死锁
- 不安全 → 可能死锁

### 检测与恢复

定期运行检测算法（O(n²)），发现环后：
- **终止进程**：选一个或多个进程终止
- **回滚**：恢复到安全状态，重启进程

选择牺牲者的依据：优先级、运行时间、已占资源等。

## 进程间通信 (IPC)

### 为什么需要 IPC？

进程拥有独立地址空间，无法直接访问彼此内存。IPC 提供通信机制。

### 两种通信模式

**直接通信**：
```c
send(P, message);    // 发送给进程 P
receive(Q, message); // 从进程 Q 接收
```

**间接通信**（通过消息队列）：
```c
send(A, message);    // 发送到队列 A
receive(A, message); // 从队列 A 接收
```

### 通信链路缓冲

| 类型 | 行为 |
|:---|:---|
| 零容量 | 发送者必须等接收者（同步） |
| 有限容量 | 队列满时发送者等待 |
| 无限容量 | 发送者从不等待 |

### IPC 实现方式

| 方式 | 特点 |
|:---|:---|
| 信号 (Signal) | 软件中断，不传数据，仅通知事件 |
| 管道 (Pipe) | 半双工，`ls \| more` 就是管道 |
| 消息队列 | 按 FIFO 管理消息，可跨进程 |
| 共享内存 | 最快，但需要额外同步 |
| Socket | 可跨网络 |

### 共享内存

```
进程 A 地址空间          进程 B 地址空间
┌──────────┐            ┌──────────┐
│          │            │          │
│  映射 ───┼── 共享段 ──┼─── 映射  │
│          │            │          │
└──────────┘            └──────────┘
```

- **优点**：无系统调用、无数据拷贝，速度最快
- **缺点**：必须自行同步（信号量/锁）
- 适合大量数据交换

### 管道示例

```bash
# Shell 管道：ls 的 stdout 连接到 more 的 stdin
ls -l | more
```

```c
// 匿名管道
int fd[2];
pipe(fd);  // fd[0] 读端, fd[1] 写端

if (fork() == 0) {
    close(fd[1]);           // 子进程关闭写端
    read(fd[0], buf, size); // 从管道读
} else {
    close(fd[0]);           // 父进程关闭读端
    write(fd[1], data, len);// 向管道写
}
```

## 学习要点总结

1. 死锁需要互斥、持有并等待、不可抢占、循环等待四个条件同时成立
2. 预防、避免、检测、忽略是四种处理策略，实际 OS 多选择忽略或部分检测
3. 银行家算法通过安全状态检查避免进入不安全状态
4. IPC 方式多样：管道简单、共享内存最快、Socket 可跨网络
5. 共享内存需要额外的同步机制配合使用
