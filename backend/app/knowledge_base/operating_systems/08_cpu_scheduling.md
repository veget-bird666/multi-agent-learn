# CPU 调度

## 背景

### 上下文切换

- 保存当前进程/线程在 PCB/TCB 中的执行上下文
- 加载下一个进程/线程的上下文
- 切换必须**快速**——调度非常频繁

### 何时触发调度？

**非抢占式**（需等待）：
- 进程从运行 → 等待（如 I/O）
- 进程终止

**抢占式**（可中断）：
- 进程从运行 → 就绪（时间片用完）
- 进程从等待 → 就绪（I/O 完成）

## 调度目标

| 指标 | 含义 | 类比 |
|:---|:---|:---|
| 响应时间 | 提交请求到首次响应的时间 | 打开水龙头立刻出水（低延迟） |
| 周转时间 | 进程从创建到完成的总时间 | — |
| 等待时间 | 在就绪队列中的总时间 | — |
| 吞吐量 | 单位时间完成的进程数 | 游泳池快速注水（高带宽） |
| CPU 利用率 | CPU 忙碌时间占比 | — |

**关键矛盾**：低延迟（交互式）和高吞吐量（批处理）往往不可兼得。

### 程序执行模型

程序在 **CPU 突发 (Burst)** 和 **I/O 等待** 之间交替：

```
CPU ████░░░░██████░░░████░░░░░  (█ = CPU, ░ = I/O)
```

每个调度决策：下一个 CPU 突发交给谁？

## 经典调度算法

### FCFS（先来先服务）

按到达顺序排队，简单但**平均等待时间波动大**。

```
进程: P1(24ms) P2(3ms) P3(3ms)
FCFS 等待: 0 + 24 + 27 = 51ms
```

短任务排在长任务后面会严重延迟。

### SJF / SRT（短作业优先 / 短剩余时间优先）

选择**预计完成时间最短**的任务。

- SJF：非抢占
- SRT：抢占式——新进程到达时若更短则抢占

- 最优平均等待时间
- **饥饿问题**：长任务可能永远得不到 CPU
- 需要预测 CPU 突发长度（可用指数加权平均）

### HRRN（最高响应比优先）

```
响应比 R = (等待时间 + 服务时间) / 服务时间
```

综合考虑等待时间和执行时间，避免 SJF 的饥饿。

### Round Robin（时间片轮转）

每个进程分配一个**时间量子 (Time Quantum)**，用完则切换到下一个。

```
时间片 = 4ms
P1 ████ P2 ████ P1 ████ P2 ████ ...
```

- 时间片太大 → 退化为 FCFS
- 时间片太小 → 上下文切换开销过大
- 经验法则：上下文切换开销 < 1%

### 多级反馈队列 (MLFQ)

多个优先级队列，不同队列不同调度策略：

```
高优先级队列 → RR（时间片小）  ← I/O 密集型停留
     ↓ 时间片用完降级
低优先级队列 → FCFS            ← CPU 密集型下沉
```

- CPU 密集型任务逐渐降级
- I/O 密集型任务保持高优先级
- 综合了 RR 的公平和优先级的效率

## 实时调度

**实时系统**：正确性依赖时间和功能两方面。

| 类型 | 要求 |
|:---|:---|
| 强实时 | 必须在截止时间内完成，否则失败 |
| 弱实时 | 尽量满足，但不保证 |

| 算法 | 策略 |
|:---|:---|
| RM（单调速率） | 周期越短优先级越高（静态） |
| EDF（最早截止优先） | 截止时间越早优先级越高（动态） |

## 多处理器调度

**SMP（对称多处理器）**：每个 CPU 运行自己的调度器，需要同步就绪队列。

### 优先级反转

高优先级任务等待低优先级任务持有的资源：

```
L 持有锁 → H 等待锁 → M 抢占 L → H 被 M 间接阻塞
```

**解决方法**：
- **优先级继承**：L 临时继承 H 的优先级
- **优先级天花板**：资源优先级 = 所有可能锁定它的进程的最高优先级

## 学习要点总结

1. 调度在上下文切换时发生，目标是平衡延迟、吞吐量和公平性
2. FCFS 简单但不公平，SJF 最优但需预测且可能饥饿
3. RR 适合分时系统，MLFQ 是现代 OS 的实用方案
4. 时间片大小的选择是 RR 的核心参数
5. 优先级反转是多线程/多处理器系统的经典陷阱
