# 进程与线程

## 进程 (Process)

### 进程 ≠ 程序

一个程序可以产生多个进程（如打开多个浏览器窗口），一个进程也可能包含多个程序（通过 `exec` 加载）。

**进程定义**：具有一定独立功能的程序在数据集合上的一次**动态执行过程**。

### 进程的组成

- 程序代码（文本段）
- 程序处理的数据
- 程序计数器 (PC) 和下一条指令
- 寄存器、堆、栈
- 打开的文件等系统资源

### 进程 vs 程序

| 对比 | 程序 | 进程 |
|:---|:---|:---|
| 性质 | 静态的代码集合 | 动态的执行过程 |
| 生命周期 | 永久保存在磁盘 | 暂时的，执行完即消失 |
| 组成 | 仅指令和数据 | 程序 + 数据 + PCB |
| 状态 | 无 | 就绪/运行/阻塞等 |

### 进程的特点

- **动态性**：可创建、挂起、终止
- **并发性**：可被独立调度（并发 ≠ 并行）
- **独立性**：各进程工作互不影响（页表是保障之一）
- **制约性**：因共享资源或同步需要而互相制约

## 进程控制块 (PCB)

OS 为每个进程维护一个 PCB，是进程存在的唯一标志。

### PCB 三大类信息

**1. 进程标识**
- 进程 ID (PID)、父进程 ID、用户 ID

**2. 处理机状态（保存现场）**
- 通用寄存器、PC、程序状态字 (PSW)、栈指针

**3. 进程控制信息**
- 调度信息（优先级、状态）
- 进程间通信信息
- 内存管理信息（页表指针）
- 打开的文件列表

### PCB 的组织方式

- **链表**：同一状态的 PCB 串成链表（就绪链表、阻塞链表）
- **索引表**：同一状态的 PCB 索引到一张表

## 进程状态

### 三种基本状态

```
        创建
         ↓
    ┌─→ 就绪 ←──────────────┐
    │    ↓ 调度              │ I/O 完成
    │   运行 ──→ 阻塞 ──────┘
    │    ↓ 时间片到
    └────┘
         ↓ 结束
        退出
```

| 状态 | 含义 |
|:---|:---|
| 运行 (Running) | 正在 CPU 上执行 |
| 就绪 (Ready) | 万事俱备，只欠 CPU |
| 阻塞 (Blocked) | 等待某事件（I/O、信号等） |

### 挂起状态

内存不足时，进程可被换出到磁盘：
- **就绪挂起**：在外存，就绪后可换入
- **阻塞挂起**：在外存，等待事件

## 线程 (Thread)

### 为什么需要线程？

以 MP3 播放器为例：

```c
// 单线程：读、解压、播放串行 → 无法并发，播放不连贯
while (1) { Read(); Decompress(); Play(); }

// 多进程：可并发，但进程间通信开销大，创建/切换成本高
// 进程1: while(1) Read();
// 进程2: while(1) Decompress();
// 进程3: while(1) Play();
```

**线程**解决了这个问题：同一进程内多条执行流，共享地址空间。

### 线程的定义

线程是进程中的**一条执行流程**。

重新理解进程：
- **资源角度**：进程 = 资源平台（地址空间、文件等）
- **运行角度**：进程 = 资源平台上的一条或多条执行流（线程）

### 线程 vs 进程

| 对比 | 进程 | 线程 |
|:---|:---|:---|
| 资源分配 | 是 | 否 |
| CPU 调度 | 否（线程被调度） | 是 |
| 地址空间 | 独立 | 共享所属进程的 |
| 创建/切换开销 | 大 | 小 |
| 崩溃影响 | 仅自身 | 可能导致整个进程崩溃 |

### 线程的三种实现

| 类型 | 实现位置 | 代表 |
|:---|:---|:---|
| 用户线程 | 用户空间线程库 | POSIX Pthreads |
| 内核线程 | 操作系统内核 | Linux、Windows |
| 轻量级进程 | 内核支持的用户线程 | Solaris |

## 上下文切换

切换进程/线程时，OS 必须：
1. 保存当前 PCB/TCB 中的 CPU 状态
2. 加载下一个 PCB/TCB 的状态
3. 恢复执行

**开销来源**：寄存器保存/恢复、页表切换（进程切换时）、Cache 失效

进程切换 > 线程切换（同进程内线程切换无需换页表）。

## 进程控制：fork / exec / wait

```c
#include <unistd.h>
#include <stdio.h>
#include <sys/wait.h>

int main(void) {
    int pid = fork();       // 创建子进程（复制父进程内存）
    if (pid == 0) {
        // 子进程：通常立即 exec 加载新程序
        execl("/bin/ls", "ls", "-l", NULL);
    } else if (pid > 0) {
        // 父进程：等待子进程结束
        int status;
        wait(&status);
        printf("子进程已结束\n");
    }
    return 0;
}
```

| 系统调用 | 作用 |
|:---|:---|
| `fork()` | 创建子进程，复制父进程地址空间 |
| `exec()` | 用新程序替换当前进程映像 |
| `wait()` | 父进程等待子进程结束并回收资源 |
| `exit()` | 进程终止，若父进程未 wait 则成为**僵尸进程** |

**Copy-on-Write (COW)**：现代 OS 在 fork 时不立即复制内存，只在写入时才复制，大幅降低 fork 开销。

## 学习要点总结

1. 进程是资源分配单位，线程是 CPU 调度单位
2. PCB 是 OS 管理进程的核心数据结构
3. 进程状态转换由调度、I/O、创建/终止等事件驱动
4. 线程共享进程资源，创建和切换开销远小于进程
5. fork + exec + wait 是 Unix 创建新程序的标准模式
