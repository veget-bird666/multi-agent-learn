# 非连续内存分配：分段与分页

## 为什么需要非连续分配？

### 连续分配的缺点

1. 物理内存必须连续
2. 内存利用率低
3. 外部/内部碎片严重

### 非连续分配的优点

1. 物理地址空间**不必连续**
2. 更好的内存利用和管理
3. 支持共享代码与数据（共享库）
4. 支持动态加载和动态链接

### 代价

需要建立**虚拟地址 → 物理地址**的映射，依赖硬件（MMU）或软件方案。

## 分段 (Segmentation)

### 核心思想

程序由不同逻辑段组成：代码段、数据段、堆、栈、`.bss` 等。分段按**逻辑意义**划分，便于分离和共享。

### 分段寻址

逻辑地址是二维的：**(段号 s, 段内偏移 addr)**

```
逻辑地址 (s, addr)
       ↓ 查段表
段表[s] = { 起始物理地址, 段长限制 }
       ↓
物理地址 = 起始物理地址 + addr
```

OS 维护**段表**：`(段号 → 物理起始地址, 长度限制)`

### 分段 vs 分页

| 对比 | 分段 | 分页 |
|:---|:---|:---|
| 划分依据 | 逻辑意义（代码/数据/栈） | 固定大小 |
| 段/页大小 | 不固定 | 固定（2 的幂，如 4KB） |
| 碎片 | 外部碎片 | 内部碎片 |

## 分页 (Paging)

### 基本结构

- **帧 (Frame)**：物理内存的固定大小块
- **页 (Page)**：逻辑地址空间的固定大小块
- 页大小 = 帧大小，通常为 512B / 4KB / 8KB

### 地址计算

**物理地址** = `(帧号 f, 帧内偏移 o)` → `2^S × f + o`

**逻辑地址** = `(页号 p, 页内偏移 o)` → `2^S × p + o`

其中 S 是偏移位数。例如 16 位地址、512 字节页帧：物理地址 `(3, 6)` = `2^9 × 3 + 6 = 1542`

### 页寻址流程

```
CPU 产生逻辑地址 (p, o)
       ↓
查页表：页号 p → 帧号 f
       ↓
物理地址 = (f, o)
```

OS 维护**页表**：`(页号 → 帧号)`

### 页表项的标志位

| 标志位 | 含义 |
|:---|:---|
| resident bit | 0 = 页不在内存，1 = 在内存 |
| dirty bit | 页是否被修改过 |
| reference bit | 页是否被访问过（用于置换算法） |

## 页表性能优化

### 问题

- 每次内存访问需要 **2 次**内存访问（查页表 + 访问数据）
- 64 位系统页表可能极大（2^54 项，放不下）

### TLB（转换后备缓冲区）

CPU 中的高速缓存，存储最近使用的页表项。

```
逻辑地址 → 查 TLB
  ├── 命中 → 直接得到帧号（快）
  └── 未命中 → 查内存中的页表 → 更新 TLB
```

### 多级页表

将页号分为多级，按需分配页表，**时间换空间**。

```
一级页号 → 查一级页表 → 得到二级页表地址
二级页号 → 查二级页表 → 得到帧号
```

若一级页表项的 resident bit = 0，则对应的二级页表不存在，节省空间。

### 反向页表

按**物理帧**索引而非逻辑页号，只需一张表，大小与物理内存成正比。

- 优势：表大小与逻辑地址空间无关
- 劣势：从页号查帧号需要搜索（可用哈希优化）

## 转换实例

16 位地址系统，32KB 物理内存，每页 1024 字节：

| 页号 | Flags | 帧号 | 结果 |
|:---:|:---:|:---:|:---|
| 4 | 101 | 0 | 内存访问异常 |
| 3 | 011 | 4 | 物理地址 (4, 1023) |

## 学习要点总结

1. 非连续分配解决连续分配的碎片和低利用率问题
2. 分段按逻辑划分，分页按固定大小划分——现代 OS 多使用分页或段页式
3. 页表是核心数据结构，每个进程有独立的页表
4. TLB 缓解页表访问的时间开销，多级页表缓解空间开销
5. 理解地址转换流程是分析缺页中断和虚拟内存的基础
