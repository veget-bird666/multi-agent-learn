# 中断、异常与系统调用

## 计算机启动过程

理解启动流程，有助于明白 OS 是如何获得控制权的。

### 启动相关组件

| 组件 | 作用 |
|:---|:---|
| Disk | 存放 OS 和 Bootloader |
| BIOS | 基于 I/O 的固件，负责最早期的硬件初始化 |
| Bootloader | 加载 OS，将 OS 放入内存 |

### Disk 结构

```
Disk
├── OS（操作系统代码和数据）
└── Bootloader（引导程序，通常占引导扇区 512 字节）
```

### 开机流程

**第一阶段：BIOS**
1. 开机后，CPU 从固定地址启动（`CS:IP = 0xF000:0xFFF0`）
2. BIOS 初始化硬件，将 Bootloader 从磁盘引导扇区加载到内存 `0x7C00`
3. 跳转到 `CS:IP = 0x0000:0x7C00`，开始执行 Bootloader

**第二阶段：Bootloader**
1. 将 OS 的代码和数据从硬盘加载到内存
2. 跳转到 OS 的起始地址，把控制权交给操作系统

## 中断 (Interrupt)

**来源**：外设（键盘、网卡、磁盘、定时器等）

**特点**：异步——应用程序不知道中断何时发生

### 中断处理流程

```
硬件                          软件
────                          ────
设置中断标记          →    保存当前 CPU 状态（寄存器等）
记录中断事件 ID       →    根据 ID 跳转到中断服务程序 (ISR)
                              ISR 处理完成后清除中断标记
                              恢复被中断的程序继续执行
```

## 异常 (Exception)

**来源**：程序自身的错误行为——非法指令、除零、缺页、访问非法内存等

**特点**：同步——执行到特定指令时**必然**发生

### 异常处理流程

1. 保存现场（寄存器状态）
2. 异常处理：
   - 杀死产生异常的程序，或
   - 重新执行引发异常的指令（如缺页后页面调入内存）
3. 恢复现场

## 系统调用 (System Call)

**来源**：应用程序**主动**请求 OS 提供服务

**特点**：通过 API 间接调用，用户无需了解内核实现细节

### 常见 API 体系

| API | 适用平台 |
|:---|:---|
| Win32 API | Windows |
| POSIX API | UNIX、Linux、macOS |
| Java API | JVM 虚拟机 |

### 系统调用的工作机制

1. 每个系统调用有唯一序号，内核维护一张**系统调用表**
2. 调用时触发 **用户态 → 内核态** 的切换
3. 切换过程：保存用户态上下文 → 切换到内核栈 → 执行内核服务 → 返回结果

### 用户态与内核态

| 状态 | 权限 | 说明 |
|:---|:---|:---|
| 用户态 (User Mode) | 低 | 不能直接执行特权指令 |
| 内核态 (Kernel Mode) | 高 | 可执行任何指令，管理硬件 |

### 跨越边界的开销

系统调用比函数调用慢，开销包括：
- 建立中断/异常/系统调用号与服务例程的映射
- 建立内核堆栈
- 验证参数合法性
- 更新页表权限（内核态与用户态地址空间切换）
- TLB 刷新

这些开销是**值得的**——它们保证了系统的安全性和稳定性。

## 三者对比

| 类型 | 源头 | 时机 | 对应用的影响 |
|:---|:---|:---|:---|
| 中断 | 外设 | 异步 | 透明，处理完继续执行 |
| 异常 | 程序错误 | 同步 | 杀死进程或修复后重试 |
| 系统调用 | 程序主动请求 | 同步/异步 | 等待 OS 完成服务 |

## 为什么应用程序不能直接访问硬件？

1. **内核是受信任的第三方**——只有内核能安全地操作硬件
2. **特权指令保护**——防止程序破坏系统或其他进程
3. **抽象与简化**——程序员通过文件、进程等概念操作，无需关心硬件细节

```c
// 用户程序通过系统调用间接访问硬件
// 例如 Linux 下的 write 系统调用
#include <unistd.h>

int main(void) {
    write(1, "Hello\n", 6);  // 1 = stdout，内部触发 sys_write 系统调用
    return 0;
}
```

## 学习要点总结

1. 启动链：BIOS → Bootloader → OS，控制权逐步从固件转移到操作系统
2. 中断来自外设（异步），异常来自程序错误（同步），系统调用来自主动请求
3. 用户态/内核态切换是 OS 安全模型的核心
4. 系统调用通过 API 封装，是应用程序访问 OS 服务的唯一正规途径
5. 理解这三者的区别，是分析 OS 行为（如缺页中断）的基础
