# 进程同步与互斥

## 为什么需要同步？

多线程/多进程**合作**时共享数据，若不加控制会导致**竞态条件 (Race Condition)**。

### 经典竞态示例

```c
// 内核中分配进程 ID
new_pid = next_pid++;  // 看似一条语句，实际是多条指令

// 机器指令序列:
// Load  next_pid → Reg1
// Store Reg1     → new_pid
// INC   Reg1
// Store Reg1     → next_pid
```

两个进程并发执行时，可能都读到 `next_pid = 100`，最终两个进程都得到 PID 100。

### 竞态条件的特征

- **不确定性**：结果依赖执行顺序
- **不可重现**：难以调试

## 核心概念

| 概念 | 定义 |
|:---|:---|
| 临界区 (Critical Section) | 访问共享资源的代码段 |
| 互斥 (Mutual Exclusion) | 同一时刻最多一个线程在临界区 |
| 原子操作 (Atomic Operation) | 不可被中断的完整操作 |
| 死锁 (Deadlock) | 多个进程互相等待，都无法继续 |
| 饥饿 (Starvation) | 进程长期得不到调度 |

### 临界区问题的三个要求

1. **互斥**：临界区内最多一个线程
2. **前进 (Progress)**：想进入的线程最终一定能进入
3. **有限等待**：线程等待进入的时间有限

可选：**无忙等待**——等待时挂起而非空转

## 实现互斥的方法

### 方法1：禁用中断

```c
disable_interrupts();
// 临界区
enable_interrupts();
```

- 仅适用于**单处理器**
- 临界区过长会导致系统无响应
- 多核 CPU 无效

### 方法2：软件方案

**Peterson 算法**（双线程）：

```c
// 线程 i 进入临界区
flag[i] = true;
turn = j;  // 礼让对方
while (flag[j] && turn == j);  // 等对方完成或让出
// 临界区
flag[i] = false;
```

**Bakery 算法**（N 线程）：按编号排队，编号最小者先进。

- 复杂，需要忙等待
- 依赖硬件提供原子 LOAD/STORE

### 方法3：硬件原子指令

**Test-and-Set**：

```c
bool TestAndSet(bool *target) {
    bool rv = *target;
    *target = true;
    return rv;
}

// 使用
while (TestAndSet(&lock));  // 若已锁则自旋
// 临界区
lock = false;
```

**Compare-and-Swap (CAS)**：现代 CPU 广泛支持，是锁和无锁数据结构的基础。

### 方法4：锁抽象（最常用）

```c
lock->Acquire();
new_pid = next_pid++;
lock->Release();
```

OS 和线程库提供 Lock 抽象，底层基于原子指令实现。

## 方法对比

| 方法 | 单核 | 多核 | 忙等待 | 复杂度 |
|:---|:---:|:---:|:---:|:---:|
| 禁用中断 | ✓ | ✗ | 否 | 低 |
| 软件方案 | ✓ | ✗ | 是 | 高 |
| 原子指令 | ✓ | ✓ | 可选 | 中 |
| 锁 | ✓ | ✓ | 可选 | 低（使用者） |

## 合作 vs 独立线程

| 特征 | 独立线程 | 合作线程 |
|:---|:---|:---|
| 共享状态 | 否 | 是 |
| 确定性 | 是 | 否 |
| 可重现 | 是 | 否 |
| 调试难度 | 低 | 高 |

## 学习要点总结

1. 竞态条件源于对共享数据的并发访问，结果不可预测
2. 互斥保证临界区同一时刻只有一个执行流
3. 看似原子的操作（如 `i++`）可能由多条指令组成
4. 现代 OS 通过锁 + 硬件原子指令实现互斥
5. 设计并行程序时，先想清楚同步策略，再写代码
