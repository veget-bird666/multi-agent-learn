# 页面置换算法

## 功能与目标

**功能**：内存已满且发生缺页时，选择哪个物理页被换出

**目标**：尽量减少缺页次数（换进换出次数）

**页面锁定**：关键页面（如 OS 内核代码）通过 lock bit 标记，不参与置换

## 评价方法

给定页面访问轨迹，模拟不同算法，比较缺页次数：

```
访问序列: 3, 1, 4, 2, 5, 2, 1, ...
物理页数: 3
```

缺页次数越少，算法性能越好。

## 局部页面置换算法

### 最优算法 (OPT)

选择**未来最长时间不会被访问**的页面换出。

- 理论最优，实际不可实现（无法预知未来）
- 用作其他算法的**性能上界**参考

### 先进先出 (FIFO)

淘汰在内存中**驻留时间最长**的页面。

```
页面队列: [3] → [3,1] → [3,1,4] → 缺页，淘汰3 → [1,4,2] → ...
```

- 实现简单（队列）
- **Belady 异常**：增加物理页数，缺页次数反而增加
- 实际很少单独使用

### 最近最久未使用 (LRU)

淘汰**最久未被访问**的页面——对 OPT 的近似。

依据局部性原理：最近用过的，将来可能还会用；久未用的，将来可能也不用。

**实现方式**：
- 链表法：访问时移到队首，淘汰队尾
- 栈法：访问时压栈并去重，淘汰栈底

**缺点**：每次访问都要更新，开销较大

### 时钟算法 (Clock / Second Chance)

用页表项的 **reference bit** 实现近似 LRU：

```
页面组织成环形链表，指针指向最老页面：

缺页时:
  若 reference = 0 → 淘汰
  若 reference = 1 → 置 0，指针前移，继续检查
```

### 二次机会算法 (Enhanced Clock)

同时考虑 reference bit 和 dirty bit：

| used | dirty | 动作 |
|:---:|:---:|:---|
| 0 | 0 | 直接淘汰 |
| 0 | 1 | 置 dirty=0，给一次机会 |
| 1 | 0 | 置 used=0 |
| 1 | 1 | 置 used=0，保留 dirty |

优先淘汰"未访问且未修改"的页（换出无需写盘）。

### 最不常用 (LFU)

淘汰**访问次数最少**的页面。

- 每个页维护访问计数器
- 与 LRU 区别：LRU 看"多久未访问"，LFU 看"访问频率"
- 问题：早期频繁访问、后期不再用的页难以淘汰

## 全局页面置换算法

### 工作集模型

**工作集 W(t, Δ)**：时刻 t 之前 Δ 时间窗口内访问过的页面集合

```
|W(t, Δ)| = 工作集大小（页面数）
```

- 进程开始执行时工作集快速扩张，稳定后大小趋于平稳
- 局部性区域变化时，工作集会跳变

### 常驻集

进程实际驻留在内存中的页面集合。

- 若 **常驻集 ⊇ 工作集** → 进程运行顺利，缺页少
- 若 **常驻集 ⊂ 工作集** → 频繁缺页，性能下降

### 工作集页置换

页面不在工作集窗口内时，直接淘汰（不等缺页）。

### 缺页率置换 (PFF)

动态调整常驻集大小，使缺页率维持在一个合理范围：
- 缺页率过高 → 增加分配的物理页
- 缺页率过低 → 减少分配的物理页

### 抖动 (Thrashing)

**现象**：物理页太少，无法容纳工作集，进程频繁换页，CPU 大量时间花在 I/O 上。

**原因**：并发进程数增加 → 每进程分到的页减少 → 缺页率飙升

**解决**：OS 需要平衡并发度和每进程的帧数。

## 算法对比总结

| 算法 | 实现难度 | 性能 | 是否 Belady 异常 |
|:---|:---:|:---:|:---:|
| OPT | 不可实现 | 最优 | 无 |
| FIFO | 简单 | 差 | 有 |
| LRU | 中等 | 好 | 无 |
| Clock | 简单 | 较好 | 无 |
| LFU | 中等 | 一般 | 无 |

> FIFO 只看"入场时间"，LRU/OPT 评估页面与程序行为的关联深度，因此 LRU 不会因增加页框而变差。

## 学习要点总结

1. 页面置换在缺页且内存已满时触发，目标是减少缺页次数
2. OPT 是理论上界，LRU 是实用的近似，Clock 是 LRU 的低开销实现
3. Belady 异常是 FIFO 独有的缺陷——更多内存反而更差
4. 工作集模型解释了为什么给进程"足够但不过量"的内存很重要
5. 抖动是内存过度分配多进程的后果，需要 OS 级别的负载控制
