# 物理内存管理

## 计算机体系结构回顾

现代计算机的三大核心组件：
1. **CPU** — 执行指令
2. **内存** — 存储运行中的程序和数据
3. **I/O** — 与外部设备交互

## 内存分层体系

```
速度 ↑  成本 ↑  容量 ↓
┌─────────────────┐
│  CPU 寄存器      │  ← CPU 直接访问，最快
│  L1 / L2 Cache  │
├─────────────────┤
│  主存 (RAM)      │  ← 程序直接寻址
├─────────────────┤
│  磁盘 (虚拟内存)  │  ← 持久化，速度最慢
└─────────────────┘
速度 ↓  成本 ↓  容量 ↑
```

- **主存**：程序运行时需要的内存空间
- **磁盘**：持久化存储，也可作为虚拟内存的扩展

## 内存管理的四大目标

| 目标 | 含义 |
|:---|:---|
| 抽象 | 提供逻辑地址空间，隐藏物理细节 |
| 保护 | 每个进程拥有独立的地址空间 |
| 共享 | 允许多个进程访问相同内存（如共享库） |
| 虚拟 | 提供比物理内存更大的地址空间 |

## 内存管理方法概览

- 程序重定位
- **分段** (Segmentation)
- **分页** (Paging)
- **虚拟内存** (Virtual Memory)
- 按需分页 (Demand Paging)

实现高度依赖硬件，**内存管理单元 (MMU)** 负责处理 CPU 的内存访问请求。

## 地址空间

| 类型 | 定义 | 范围 |
|:---|:---|:---|
| 物理地址空间 | 硬件实际支持的地址 | `[0, Max_sys]` |
| 逻辑地址空间 | 程序"看到"的地址 | `[0, Max_prog]` |

程序使用逻辑地址，MMU 将其转换为物理地址。

## 连续内存分配

连续分配：为程序分配一块**连续的**物理内存。

### 内存碎片

| 类型 | 定义 | 示例 |
|:---|:---|:---|
| 外部碎片 | 分配单元之间的空闲内存无法利用 | 总空闲 100KB，但最大连续块只有 30KB |
| 内部碎片 | 分配单元内部未使用的空间 | 请求 7KB，分配 8KB 页，浪费 1KB |

### 三种动态分区分配策略

| 策略 | 做法 | 优点 | 缺点 |
|:---|:---|:---|:---|
| 首次适配 (First Fit) | 找第一个足够大的空闲块 | 简单，易产生大空闲块 | 外部碎片，性能不确定 |
| 最优适配 (Best Fit) | 找最小的足够大的空闲块 | 小请求时效率高 | 产生大量微小碎片 |
| 最差适配 (Worst Fit) | 找最大的空闲块 | 分配快，中等请求效率高 | 易破碎大空闲块 |

> 三种策略没有绝对优劣——无法预知未来的内存请求模式。

### 碎片整理

**压缩式整理**：移动进程合并碎片
- 要求程序可重定位
- 只能在进程等待状态时移动
- 内存拷贝开销大

**交换式整理 (Swapping)**：将等待进程换出到磁盘

```
换出前:  主存 [OS | P1 | P3 | P2 | P4]   磁盘 [空]
P3 需要更多内存 →
换出后:  主存 [OS | P1 | P3 | P2]         磁盘 [P4]
```

## 学习要点总结

1. 内存层次：寄存器 > Cache > 主存 > 磁盘，速度与容量成反比
2. 连续分配简单但会产生碎片——外部碎片和内部碎片
3. 首次/最优/最差适配各有适用场景，没有万能策略
4. 交换 (Swapping) 是早期解决内存不足的方法，以时间换空间
5. MMU 是硬件与 OS 内存管理的桥梁
